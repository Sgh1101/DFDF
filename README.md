# DFDF

브라우저에서 바로 하는 5대5 공격/수비 전술 FPS입니다. 공격팀은 스파이크를 설치하고, 수비팀은 막거나 해제합니다.

## 게임

- **요원**: 42명, 능력 168개. 요원마다 Q/E/C/X 능력 4개가 있습니다. 최초 요원 목록은 `js/engine/agents.js`이며 `js/legacy/`의 여러 묶음이 보완합니다.
- **멀티플레이**: PeerJS(WebRTC) P2P. 대기실의 빈 자리는 AI 봇으로 채울 수 있습니다.
- **성장**: 계정, 레벨/XP, 골드, 랭크, 미션, 뽑기, 스킨.
- **관리자 페이지**: `admin.html` (`/admin`).
- **PWA**: `manifest.webmanifest`, `sw.js`. Vercel에 배포됩니다.

## 그래픽과 사운드

효과음, 초상화, 일부 텍스처는 코드로 만듭니다. 맵 표면 재질과 하늘 조명은 파일을 씁니다.

- `assets/mat/`: 표면 재질 webp 54개 (색, 노멀, ORM). `play.html`이 `assets/mat/<재질>_<종류>.webp`로 불러옵니다.
- `assets/env/`: 하늘 조명 HDR 7개 (alpine, city, dawn, forest, park, studio, warehouse). `assets/env/<이름>.hdr`로 불러옵니다.
- 출처는 `assets/CREDITS.md`에 있습니다 (CC0).

## 스킨 연출과 포구 맵

- **킬 효과**: 처치마다 두 음 "타-단"이 나고, 연속 처치(4.5초 안)할수록 음이 오음계로 올라가 에이스에서 끝납니다. 영웅 이상 스킨은 종·울림을 더하고 배너 색이 스킨을 따릅니다. 스킨 31종은 각자 킬배너가 있습니다 (`js/legacy/61-kill-banners.js`). 소리와 모양만 바뀌고 전투에는 영향이 없습니다.
- **총소리**: 기본 총소리 밑에 총 크기에 따른 저음·몸통·꼬리를 깝니다 (`js/legacy/63-heavier-gunshots.js`).
- **해안 포구**: 구역별 색·재질, 랜드마크(크레인, 등대, 시계탑, 터미널), 창문·소품·조명으로 꾸민 맵입니다. 충돌체와 이동 격자는 꾸미기 전과 같습니다 (`js/legacy/76-*`, `77-*`).
- **랭크전**: "같이 하기"의 `랭크전 찾기`로 열린 랭크 방에 들어가거나 새로 엽니다. 랭크 방에서는 관리자 설정, 치트와 치트 코드, 계정별 치트 권한, 운영자 방 명령, 방장의 규칙 변경이 모두 꺼지고 모드·맵·라운드는 방을 열 때 정해진 대로 갑니다. 서버는 랭크 방에서 시작한 경기의 확인표에만 랭크 표시를 서명하고, 사람이 `rank.minHumans`명 이상일 때만 RR을 바꿉니다. 일반 경기는 XP와 골드만 줍니다 (`js/legacy/81-ranked-*.js`, `api/v1.js`의 `match_start`·`progress`·`room_up`).
- **시프트 아레나**: 90 × 110 m, 3대3. 가운데 단상과 계단, 블록과 엄폐물, 양옆 탑, 사이트 단상이 있고 세 묶음의 높은 장벽이 22초마다 한 묶음씩 내려갔다가 올라옵니다. 바뀌기 3.5초 전에 해당 장벽이 주황색으로 깜빡이고 화면에 카운트가 뜹니다. 시계는 방장이 가지고 손님에게 알리며, 라운드가 시작되면 처음 모양으로 돌아갑니다 (`js/legacy/82-shift-arena-*.js`).
- **장전**: 총마다 다르게 갈아 끼웁니다. 소총·SMG는 탄창을 빼서 새로 끼우고 노리쇠를 당기고, 권총은 손잡이 탄창을 바꾸고, 펌프·반자동 산탄총은 한 발씩 넣고, 저격총(볼트액션)은 노리쇠를 올려 당긴 뒤 탄창을 바꾸고 밀어 닫습니다. 리볼버·핸드캐논은 실린더를 빼서 탄피 6개를 털고 스피드로더로 넣고, 더블배럴·산탄 권총은 꺾어 열어 두 발을 버리고 넣은 뒤 탁 닫습니다. 기관총은 덮개를 열고 탄통을 바꾼 뒤 덮개를 닫고 장전 손잡이를 당기고, RPG는 로켓을 앞으로 밀어 넣은 다음 탄두 캡을 빼고 공이를 젖힙니다 (`js/legacy/54-reload-animation.js`).
- **RPG**: RPG-7 모양입니다. 강철 발사관, 나무 열차폐판 두 개, 뒤쪽 나팔형 분사구, 권총 손잡이와 앞손잡이, 가늠쇠·가늠자, 왼쪽 광학 조준경, 멜빵 고리, 앞에 튀어나온 PG-7V 탄두(원뿔 머리, 띠, 신관)가 있습니다 (`js/legacy/52-projectiles.js`).
- **칼 돌리기**: 칼은 따로 돌고 손과 팔은 그대로입니다. 대부분은 손잡이 가운데가 축이고, 카람빗은 실제처럼 **검지가 낀 링**이 축입니다. 손가락은 손잡이를 감싸고 칼이 돌 때 펴집니다. 점검(Y)은 칼마다 다릅니다 — 기본 칼은 손가락으로 한 바퀴와 토스, 발리송은 손잡이를 부채처럼 돌리고 롤오버 뒤 공중 토스, 접이식은 두 번 접었다 튕겨 열고 손바닥 토스, 탄토는 칼날을 아래로 한 역수 전환과 찌르기, 쿠크리는 묵직한 풍차 돌리기와 내려치기입니다. 카람빗은 앞으로 두 바퀴, 뒤돌리기, 칼이 누워 도는 헬리콥터, 던져 두 번 돌려 링으로 받는 연속 기술이고 칼날 뒤로 빛 잔상이 남으며 받을 때 맑은 소리가 납니다. 가만히 들고 있으면 칼마다 짧은 묘기를 가끔 보여 줍니다 (`js/legacy/83-knife-tricks-*.js`).
- **일일 상점**: 무기고의 `상점` 탭. 매일 자정(한국 시간)에 스킨 20개(일반 7·희귀 6·영웅 4·전설 3)가 바뀌고 모두에게 같은 목록이 뜹니다. 뽑기와 달리 원하는 스킨을 골라 골드로 바로 삽니다. 가격은 뽑기보다 비싸게 정했습니다: 일반 1,200 · 희귀 3,000 · 영웅 7,000 · 전설 15,000 골드, 칼 모양 스킨은 1.5배 (뽑기 1회 300). 구매 버튼은 두 번 눌러야 사지고(첫 번째는 확인), 골드가 모자라면 얼마가 부족한지 보여 줍니다. 목록은 서버가 날짜와 비밀키로 정하므로 내일 목록을 미리 알 수 없고, 살 때 서버가 오늘 목록을 다시 계산해 확인합니다 (`shop`, `shop_buy`). 스킨을 얻는 길은 뽑기와 상점 두 가지입니다. 운영자는 '게임 설정 → 일일 상점'에서 열기·닫기, 등급별 개수, 가격, 칼 배율을 정하고, 대시보드에서 오늘 목록을 보고 `상점 새로 고침`으로 바로 바꿉니다. 구매는 서버 로그(상점)와 대시보드(상점 구매 수·쓴 골드)에 남습니다.
- **스킨 정리 (909개)**: 무늬 없이 단색이라 밋밋하던 흑요석(일반)·얼음(희귀)·홀로그램(전설)을 뺐습니다. 가지고 있던 계정은 다음 접속 때 하나에 뽑기 1회 값(홀로그램은 3회 값)의 골드를 돌려받습니다. 새로 영웅 3개(**비단잉어**: 물결과 연잎 사이의 잉어와 금박, **금이음**: 검은 도자기를 금으로 이은 균열이 은은히 빛남, **프리즘**: 색이 흐르는 다면체 무늬)와 전설 3개(**심해**: 빛나는 해파리와 부유물, **신스웨이브**: 줄무늬 해와 빛나는 격자, **오팔**: 우윳빛 돌에 온갖 색이 번쩍이고 보는 각도에 따라 무지개빛이 도는 재질)를 넣었습니다. 새 스킨은 512px로 그리고 가장자리가 이어지게 그려 총 위에서 이음매가 보이지 않으며, 몸체에 투명 코팅(클리어코트)이 있습니다. 뺀 스킨은 목록 자리에 남아 방에 보내는 스킨 번호가 바뀌지 않습니다 (`gone` 표시, 서버는 `RETIRED`).
- **칼 10종**: 기본 칼 외에 칼 스킨이 10가지이고 등급이 고루 있습니다. 일반: **총검**(톱니 등날, 총구 고리, 소총 고정쇠), **거트 나이프**(등날의 갈고리). 희귀: 접이식 나이프, **보위 나이프**(긴 클립 포인트, 놋쇠 가드, 가죽 고리 손잡이). 영웅: 탄토, 쿠크리, **쿠나이**(잎 모양 양날, 끈 감은 손잡이, 끝의 링). 전설: 카람빗, 발리송, **스틸레토**(칼날이 손잡이 앞으로 튀어나오는 자동 칼). 칼마다 손잡는 자리, 꺼낼 때 동작, 점검(Y) 동작, 가만히 있을 때 동작, 두 가지 베기가 따로 있습니다. 쿠나이는 링이 제자리에 있는 채로 칼이 링을 축으로 돌고, 스틸레토는 칼날을 넣고 손잡이를 돌리다 던진 공중에서 칼날이 딸깍 튀어나옵니다. 전설 칼(카람빗·스틸레토)은 빨리 돌 때 빛 꼬리가 남습니다. 새 칼은 방에 보내는 스킨 번호가 바뀌지 않게 스킨 목록 맨 끝에 붙였습니다 (`js/legacy/67-knives.js`, `83-knife-tricks…js`, `58-gun-skins.js`).
- **에임 보정**: 조준 중(시점을 돌리거나, 쏘거나, 정조준하거나, 움직일 때)에 조준선 가까이 보이는 적 쪽으로 시점이 조금 기울고, 그 적이 움직이면 조금 따라갑니다. 벽 너머 적, 거리·각도 밖의 적은 무시하고 내가 돌리는 쪽이 항상 이깁니다. **모바일**은 누구나 무료로 설정의 `에임 보정` 스위치로 켜고 끕니다(기본 켬, 세기 약하게·보통·강하게). **컴퓨터**는 운영자가 '가입자 → 에임 보정'에서 허용한 계정(기한 지정 가능)이나 관리자 모드에서만 쓸 수 있고, 관리자 조절판의 개인 설정에도 스위치가 있습니다. 랭크전에서는 컴퓨터 보정이 항상 꺼집니다. 운영자는 '게임 설정 → 에임 보정'이나 대시보드에서 모바일·컴퓨터를 따로 끄고, 세기(%)·거리(m)·각도(도)를 정하고, 계정마다 모바일 보정을 막을 수 있습니다 (`js/legacy/84-aim-assist…js`, `api/v1.js`의 `aim`).
- **운영자 대시보드**: 한눈에 보기(가입자·오늘/7일 접속·열린 방과 인원·누적 경기·골드·뽑기·티어 계정), 14일 가입 추이 막대, 티어 분포, 오늘 하루 로그(로그인·가입·게스트·로그인 실패·방·전설 뽑기), 권한 현황(관리자·치트 권한·PC 에임 보정·차단), 티어·처치 상위 5명, 최근 운영 기록, 저장소 사용량. 위의 칩으로 점검 모드·새 가입·게스트·방 목록·치트·모바일/PC 에임 보정을 바로 켜고 끄고, '빠른 조절'에서 공지, 에임 보정 세기·거리·각도, 방 인원, 골드, 뽑기 비용, RR을 바로 바꿉니다. 요약은 `a_summary` 한 번(계정은 MGET 한 번)으로 가져오고, 사용량을 아끼려고 자동으로 새로 고치지 않습니다.

- **달리는 열차**: 3대3 맵. 해 질 녘 나란히 달리는 화물열차 두 대 위에서 싸웁니다. 두 열차 사이를 잇는 다리 다섯 개가 세 묶음으로 나뉘어 20초마다 한 묶음씩 닫히고(3초 전에 깜빡임), 어느 묶음이 닫혀도 모든 곳에 갈 수 있습니다. 바깥의 땅·전봇대·나무가 지나가고 덜컹 소리가 납니다. 시계는 방장이 가지고 손님에게 알립니다 (`js/legacy/86-runaway-train…js`).
- **새 요원 2명 (42명)**: 기존 160개 능력과 겹치지 않게 만들었습니다. **가면**(척후대) — *흉내*: 40m 안에서 적이 25초 안에 마지막으로 쓴 능력(궁극기 제외)을 그대로 따라 씀(능력 칸에 따라 할 능력 이름이 뜸), *변장*: 8초 동안 적 화면에서 그 팀 요원의 모습·색으로 보이고 적 봇은 5m 밖이면 노리지 않음, 첫 발 +50%, 쏘거나 맞으면 풀림, *바꿔치기*: 조준한 적과 총을 맞바꿈, *탈바꿈*(궁극기): 조준한 적과 체력·방어구를 맞바꿈. **심판**(감시자) — *옐로카드*: 8초 동안 쏠 때마다 체력 -4(두 번째 카드는 -8, 최대 40), *타임아웃*: 4초 동안 8m 안에서 양 팀 누구도 피해를 주고받지 않음, *오프사이드*: 18m 선을 긋고 넘어오는 적은 5초 동안 주는 피해 절반, *레드카드*(궁극기): 조준한 적을 자기 팀 시작 지점으로 보내고 5초 능력 봉인. 맞히기·옮기기·체력 변화는 모두 방장이 정해 손님에게 알립니다 (`js/legacy/87-two-more-agents…js`).
- **랭크 시즌**: 4주마다(첫 시즌 2026-10-01 시작, 한국 시간) 시즌이 끝납니다. 끝나면 계정마다 RR이 50%만 남고, 그 시즌 랭크전을 3판 이상 한 계정은 마친 티어에 따라 골드(아이언 100 … 플래티넘 1,000 … 레디언트 5,000)를 받고, 골드 티어 이상은 시즌 전용 스킨 **월계관**(초록 칠 위의 금빛 월계관과 별, 전설)을 모든 총에 받습니다. 월계관은 뽑기·상점·찜하기에 나오지 않습니다. 보상은 계정이 다음에 접속할 때 서버가 넣고(`ensureWallet`의 `seasonRoll`), 첫 화면과 홈페이지에 한 번 알림이 뜹니다. 티어 칩과 홈페이지에 시즌 번호·남은 날·이번 시즌 랭크전 수가 보입니다. 운영자는 대시보드의 시즌 칸에서 티어별 골드, 전용 스킨 받는 티어를 바꾸고 `지금 시즌 끝내기`로 오늘부터 새 시즌을 시작하며, '게임 설정 → 시즌'에서 길이·남는 RR 비율·최소 판수를 정합니다. 스킨은 940개가 되었습니다 (`api/v1.js`의 `season`, `js/legacy/88-seasons…js`).
- **짧은 가로 화면**: 요원 선택의 맵·모드 칩은 `맵 · 모드 ▾` 버튼 하나로 접히고, 누르면 아래에서 올라옵니다 (`css/review-fixes.css`, `js/select-compact.js`).

## 테스트

`npm test`는 단위 테스트(`tests/`)입니다. 브라우저 검사(`npm run test:browser`, `test:regression`, `test:startup`, `test:maps`, `test:online`, `test:ranked`, `test:shift`, `test:reload`, `test:knife`, `test:aim`, `test:admin`, `test:shop`, `test:modes2`, `test:wish`, `test:train`, `test:agents4`, `test:season`, `test:followup`)는 Playwright가 필요하고 `DFDF_PLAYWRIGHT_MODULE`, `DFDF_BASE_URL` 등을 설정합니다. 소프트웨어 GL(헤드리스) 환경에서는 느려서 `test:regression`의 첫 클릭과 `test:followup`의 실제 클릭이 간헐적으로 시간 초과됩니다. 코드를 바꾸지 않은 브랜치에서도 같았습니다.

## 개발과 검증

Node.js 20 이상에서 `npm run dev`로 정적 페이지와 `/api/v1`을 실행합니다. 실제 계정 기능에는 위 Redis 환경변수가 필요합니다. 환경변수가 없으면 저장 요청이 실패하며 운영 데이터를 흉내 내지 않습니다.

- `npm run check`: 서버, 기능 모듈 및 HTML의 인라인 스크립트 문법 검사.
- `npm test`: 임시 메모리 저장소로 인증 경계, 동시 저장, 보상 재시도, 입력·능력·피니셔 조건 검사. 운영 Redis의 통합 검증은 별도로 필요합니다.
- `npm run test:browser`: 실행 중인 개발 서버에서 작은 가로 화면의 홈·요원 선택·무기고·처치·결과·로그아웃을 검사합니다. Playwright와 Chromium이 필요합니다. 선택적으로 `DFDF_BASE_URL`, `CHROME_BIN`, `DFDF_PLAYWRIGHT_MODULE`, `DFDF_THREE_PATH`를 설정할 수 있습니다.
- `npm run test:maps`: 문·순간이동 장치·집라인의 맵 재로딩 후 자원 해제, 중복 해제 방지, 공유 자산 유지, 문 조작 및 반복 렌더링 검사.
- `npm run test:home-layout`: 상단 메뉴와 원래 플레이 버튼·로고·요원·계정 칩 스타일 유지, 5개 화면 크기의 경계·겹침·실제 메뉴 클릭 검사. [수정 화면](docs/HOME_LAYOUT.md).
- `npm run test:startup`: 엔진 로딩 전 무기고 버튼 표시, 스킨 바로가기, 지연된 보유품 조회·뽑기 및 화면에 보이는 최종 요원 사진 검사.
- `npm run test:followup`: 방 목록 갱신·정렬·실패 표시, 요원 전용 그래픽 자원 해제, Chromium CDP 멀티터치·취소, 배치 편집·복원, 계정 전환·다른 탭 로그아웃과 한국어/영어 화면 검사. API는 테스트 저장소로 대체하며 서비스 워커를 막아 요청을 정확히 대체합니다. 모바일 실기기나 운영 데이터 검증을 뜻하지 않습니다.
- `js/game-rules.js`: 입력·능력·승패·피니셔의 공통 규칙.
- `js/game-events.js`: 온라인 처치 정보, 피니셔, 재접속 보호, 결과 완료 사건.
- `js/home.js`, `js/home-details.js`, `css/home.css`: 홈 동선, 최근 설정·즐겨찾기·모드 안내·장착 스킨과 미리보기.
- `js/home-navigation.js`, `css/home-navigation.css`: 상단 메뉴·계정 배치와 원래 홈의 위치·크기 조정.
- `js/damage-cause.js`: 지연 피해의 발사 당시 무기·스킨.
- `js/modal-focus.js`: 주요 모달의 키보드 포커스.
- `js/portrait-loader.js`: 부팅 후 화면에 보이는 요원 사진을 작업별로 생성하고, 교체된 카드의 대기 작업 정리.
- `js/game-boot.js`: 모든 스크립트 로딩 뒤 프레임·초대 연결 시작.
- `npm run test:regression`: 추가 홈 기능·실제 RPG 폭발·부활·수류탄·반복 경기 검사.
- `npm run test:network-recovery`: 실제 게임을 두 브라우저에서 실행하고 통제된 전송으로 채널 단절·재접속·진행 중 참가를 검사합니다. WebRTC/ICE/TURN 성공 검사는 아닙니다. [멀티 검사 기록](docs/MULTIPLAYER_VERIFICATION.md).
- `npm run test:online`: 두 브라우저의 실제 WebRTC 연결 검사. 테스트용 `peer` 패키지와 PeerJS 브라우저 파일이 필요하며 `DFDF_PEER_SERVER_MODULE`, `DFDF_PEERJS_PATH`로 경로를 지정할 수 있습니다. 로컬 신호 서버를 9000번 포트에서 실행합니다.
- 구조와 로딩 규칙은 [소스 안내](docs/SOURCE_LAYOUT.md)에 있습니다.
- `js/game-audio.js`, `js/client-request.js`: 공통 오디오 출력과 요청 시간 제한.

전체 작업 계획과 남은 항목은 [개발 메모 #17](https://github.com/Sgh1101/DFDF/issues/17)에 기록합니다.

실제 Redis의 Lua 저장 경로는 임시 Redis 인스턴스를 실행한 뒤 `DFDF_REDIS_CLI`와 `DFDF_REDIS_SOCKET`을 지정해 `npm test`로 검사할 수 있습니다. 지정하지 않으면 해당 통합 테스트 하나를 건너뜁니다. 테스트 API 요청은 운영 서버로 전송하지 않습니다. `test:online`은 브라우저가 WebRTC 연결을 허용하는 환경이 필요합니다. 관리 정책으로 직접 UDP가 차단되고 TURN도 없는 환경에서는 연결 실패를 보고하며, 성공한 검증으로 간주하지 않습니다.

소유자와 관리자 인증 형식을 갱신했으므로 적용 후 해당 계정은 다시 로그인해야 합니다. 일반 계정은 비밀번호 초기화 또는 새 세션 발급에 따라 이전 세션이 무효가 될 수 있습니다. 보상은 유효한 경기 확인표가 있어야 지급되며, P2P 호스트의 경기 자체를 서버가 검증하는 구조는 아닙니다.


현재 RR은 AI전·비공개 방·관리자 설정 경기를 포함한 완료 경기 결과에 반영되며 무승부는 0입니다. 사격 연습과 맵 탐방은 결과를 적립하지 않습니다. 온라인 일반전만 반영하도록 바꾸는 선택은 아직 확정되지 않아 기존 경기 정책을 유지합니다.

세션 버전이 없는 이전 로그인은 다시 로그인해야 합니다. 경기 보상 확인표도 해당 계정의 세션 버전에 묶으므로, 비밀번호 초기화 또는 삭제·재가입 이전의 확인표는 사용할 수 없습니다. 업데이트 전에 발급한 이전 형식의 확인표는 새 경기 시작 후 새 확인표로 대체됩니다.
