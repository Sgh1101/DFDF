## 좌표와 이동

`manifest.layout`의 각 배열은 `[sourceX,sourceZ,worldFloorY]`다. X/Z는 `(source - sourceCropMin - dimensions/2) * horizontalScale`로 바꾼다. Y는 원본 높이 배율을 적용한 바닥 높이다. 공격[175,55,7.5], 수비[155,185,11.25], A[95,145,13.75], B[225,148,5], 미드[160,120,10]. A/B는 반경8m다.

예전의 공격[95,193]은 바깥 장식 구역, A[220,177]은 빈 공간을 가리켰다. 이 좌표를 가장 큰 그래프에50m 넘게 밀어 넣던 동작은 제거했다. 원본/공식 어센트 평면과 실제 연결 바닥을 확인해 좌표를 정했고, 현재 필수 구역의 자동 이동량은0m다.

다리 위와 아래를 별도 노드로 가진 다층 그래프를 만든다. 반 블록 간격0.875m, 블록 중심을 포함하도록 격자를 정렬한다. 각 링크는 실제 `moveWithSlide` 몸체·계단 판정으로 검사한다. 공격 시작점과 양방향으로 연결된 구역만 스폰/목표로 사용하고, 필수 좌표가3m 안에서 연결되지 않으면 오류를 낸다. 경로는 층 높이를 반영하며 목표별 역방향 경로를 최대12개 보관한다. 임시 능력 벽에 대한 실시간 전역 재탐색은 기존처럼 별도 한계다.

## 재생성

`node scripts/build-ascent-district.js <원본.schematic>`로 만든다. 입력 SHA가 다르면 쓰기 전에 중단한다. 입력 없는 `npm run build:original-maps`는 저장된 원본 지형/충돌 해시를 확인하고 모바일 패키지와 메타데이터만 재생성한다. 다른 마을로 대체하지 않는다. 색 변경 후에는 `python scripts/paint-block-textures.py`, `python scripts/package-mobile-map.py`, `node scripts/build-ascent-district.js` 순서로 실행한다. 사이트 미리보기는 `node scripts/dump-site-data.js --maps=ascent_trial`로 실제 렌더링한 뒤 `node scripts/build-site-pages.js`를 실행한다.

## 검증 범위

원본 지문/치수/단차·모바일 충돌 일치/캐시를 단위 검사한다. 브라우저에서는 실제 키보드 이동, 양 팀에서 양쪽 사이트까지4개 전체 경로, 벽 몸체/총알 충돌, 천장 충돌, 봇9명 이동,112개 능력 발동 및4개 그래픽 모드의 장판 높이를 검사한다. 실제 Android 기기 및 WAN 품질을 검증했다고 표현하지 않는다. 원본이 커진 만큼 예전 단순 마을보다 메모리·다운로드가 크며 모바일 실기기 성능은 별도 확인 대상이다.

설치 구역과 폭탄 메시/설치 애니메이션/폭발 효과는 실제 바닥 높이를 따른다. 다른 층에서 설치·줍기·해제를 할 수 없다. 네트워크 스파이크 배열의 선택적6번째 값으로 높이를 전달하며 기존5개 값을 읽는 형식과 호환된다. 적 정보/목표/봇 경로와 원격 궁극기 좌표 선택에도 높이를 유지한다. 실제 브라우저에서 같은 X/Z의13.75m↔18.75m 목표 변경·봇 추적, 아래층 설치/해제 방지, 양 사이트 수동 설치/해제, 로컬 WebRTC 폭탄 높이·방장과 다른 층으로 참가자 순간이동을 검증한다. 미리보기는 지형의8개 경계 모서리가 화면 안에 들어가도록 카메라를 맞춘다.
