# 수정 및 검증 기록

기준: main `335ceb92aaaed6c4d97fe6ed51a50a6f22af001e`. 전체 계획: [#17](https://github.com/Sgh1101/DFDF/issues/17).

## 변경

- `api/v1.js`: 소유자 인증을 방·PeerJS 연결에 묶인 5분 확인표로 교체. 플레이어·관리자 토큰과 용도를 구분하고 이전 소유자/관리자 형식은 재로그인 필요. 공통 차단 검사, 비밀번호 초기화 후 세션 무효화, 원자적 계정 저장과 충돌 재시도, 설정 범위 검증, 오래된 설정 쓰기 거절.
- 경기 결과는 유효한 확인표가 필요하며, 계정 갱신·확인표 소비·30일 응답 영수증 저장을 Redis Lua에서 함께 처리. 재전송 시 같은 보상과 현재 계정 정보를 반환. 무승부 RR 유지.
- `play.html`: 중복 백그라운드 워커 제거, 남은 워커 수명 관리, 호스트 능력 검증·사용량 소비·환불·응답, 입력 검증, DM 순위 일치, 구조화된 승패와 완료 사건, 결과 재시도 기록, 터치 모드/배치 저장 분리, 계정별 캐시, 미션 중복 조회 방지, 설정 도착 후 맵 목록 반영.
- `js/game-events.js`: 처치 당시 무기·스킨·모드·라운드 전달, 참가자 피드백, 사격 음색 전달, 재접속 증명, 일반전의 마지막 적 무기 처치에서 짧은 3D 피니셔. 점검/꺼내기 모션과는 별개이며 피해·조작·경기 시간을 바꾸지 않음.
- `js/home.js`, `css/home.css`: 상단 계정/랭크/골드/미션 통합, 연습 메뉴, 최근 설정, 첫 플레이 안내, 무기고 진입 정리, 목록에서 파생한 표시 개수, 명시적인 사운드·피니셔 미리보기 및 정지.
- `js/client-request.js`, `js/game-audio.js`, `js/match-report.js`, `js/game-rules.js`: 요청 시간 제한, 공통 오디오 출력, 경기별 확인표 수명, 공통 입력·능력·승패·피니셔 규칙.
- `index.html`, `admin.html`, `privacy.html`, `README.md`: 로그아웃 후 전적 제거, 다른 탭의 세션 변경 처리, 점검/네트워크 실패 구분, 관리자 타이머·비밀번호 입력·개수, 실제 저장 정보와 실행 문서.

## 1차 검증

- `npm run check`: 게임의 인라인 스크립트 80개, 홈페이지·관리자 스크립트, 서버와 새 기능 모듈 문법 통과.
- `node --test tests/*.test.js`: 인증 용도/범위/만료, 소유자 확인표 실패 후 재시도, 연결 교체·종료 후 늦은 권한 응답 거절, 동시 저장, 설정 시각, 무승부, 보상 재시도, 최신 계정 보존, 입력과 실제 호스트 능력 요청, 경기 확인표 중복 발급 방지 검증.
- 임시 Redis 7.4.2에 실제 Lua 실행: 동시 뽑기 3개 전부 반영, 확인표/응답 영수증을 통한 보상 한 번 지급, 미션 보상 중복 수령 방지.
- 로컬 Chromium/Playwright: 홈 화면 1440×900 및 852×393 확인, 작은 가로 화면에서 요원 능력 4개와 맵 목록, 무기고 미리듣기·피니셔 미리보기/정지, 일반전 실제 사격 마지막 처치의 피니셔, 잘못된 온라인 입력 거절, 구조화된 결과, 로그아웃 후 전적 숨김 확인. 테스트 계정 API는 임시 메모리 저장소 사용.
- 별도 읽기 전용 보안 검토에서 원래 소유자 자격 증명 전달 경로의 잔여 우회가 발견되지 않음. 확인표 중복 발급과 재시도 시 오래된 계정 정보 반환 지적은 재현 조건을 테스트로 추가하고 수정.

원래 경로는 `own-hi`에 플레이어 토큰을 포함했지만 지금은 용도가 분리된 확인표만 전송합니다. 해당 확인표로 `me` 또는 관리자 기능을 호출하면 거절되며, 정상 소유자 로그인과 관리자 기능은 테스트에서 유지됩니다.

## 2차 변경과 검증

- RPG·수류탄은 발사 시 처치자·무기·스킨·라운드를 고정합니다. RPG 총소리도 발사 원인을 사용하고, 현재 총을 바꾼 뒤 터져도 RPG 스킨으로 처치 사건을 전달합니다. 이전 라운드의 투사체는 종료하고, 사라진 발사자의 폭발을 다른 플레이어에게 돌리지 않습니다.
- 피니셔의 소리·3D 효과를 라운드당 한 번으로 제한했습니다. 부활 뒤 같은 적을 다시 죽여도 재발동하지 않습니다. 수류탄·스킬·환경사·자살은 제외합니다. 실제 사망이 취소되면 상태를 소비하지 않습니다. 에이스는 서로 다른 희생자로 집계합니다.
- 참가자가 라운드 상태보다 처치 사건을 먼저 받는 경우 최대 4초 동안 대기시킨 뒤 같은 라운드에서만 처리합니다. 재접속·새 경기·종료 때 대기 사건과 연출을 정리합니다.
- 결과에서 홈으로 이동할 때 남아 있던 구매·설정·관리자·무기고 창을 닫습니다. 구매 창을 닫는 코드가 메뉴에서 마우스를 고정하던 경로도 막았습니다.
- 최근 설정에 난이도를 포함하고 유효한 요원·맵·모드만 복원합니다. 계정별 요원 즐겨찾기와 역할 필터의 교집합, PC/모바일 조작 안내, 맵 크기에 따른 모드 목표·부활·팀 규모, 장착 스킨 요약과 해당 무기고 진입을 추가했습니다. 표시 개수는 실제 목록에서 계산합니다.
- 설정·구매·관리자·무기고·미션 창에 포커스 순환과 닫은 뒤 복원을 적용했습니다. 무기고가 Tab 입력을 가로채던 기존 처리도 수정했습니다.
- 모션 줄이기 및 저사양 홈에서 카메라와 자동 맵 변경을 멈추고 배경 렌더링을 초당 최대 2회로 줄입니다. 새 피니셔도 OS 모션 줄이기와 게임의 연출 설정을 따릅니다.
- 인라인 스크립트 80개를 `js/legacy/`로 분리하고 순서를 기록했습니다. 압축된 엔진을 정렬하고, 전체 로딩 뒤 프레임·초대 참가를 시작하는 부팅 관리와 실패 안내를 추가했습니다. 기존 전역 함수 래퍼를 모두 제거한 재작성은 아닙니다. 구조는 [SOURCE_LAYOUT.md](SOURCE_LAYOUT.md)에 있습니다.
- `npm run check`: 인라인 진입 스크립트와 하위 폴더를 포함한 외부 스크립트 90개 파싱.
- 임시 Redis 7.4.2를 지정한 `npm test`: **26개 모두 통과**, 건너뛴 검사 없음. 추가 검사는 지연 피해 원인 보존, 실제 백그라운드 워커의 중복 생성 방지·시간 분할·종료, 부팅 대기·취소·실패 처리입니다.
- `npm run test:regression`: 요원 즐겨찾기·역할 필터, 모드 설명, 무기고 Tab 순환·포커스 복원, 고정 배경, 실제 RPG 발사→무기 교체→폭발, 부활 뒤 중복 방지, 수류탄 제외, 최근 난이도, 일반전/TDM 12회 반복 진입·종료 검증 통과. 반복 검사에서 남은 투사체·피니셔가 0이고 요원이 10명 이내였습니다. GPU 메모리 안정성 또는 여러 시간의 성능을 증명하는 검사는 아닙니다.

## 모바일 버튼 배치 보완

- `css/mobile.css`: 짧은 가로 화면의 홈 메뉴를 두 개의 플레이 카드로 배치. 최근 설정은 반 폭 버튼, 연습·무기고·설정은 3열로 정리. 좁은 화면의 요원 소개 줄을 숨기고, 연습 메뉴는 잘리지 않게 안쪽으로 펼침.
- 기본 전투 능력 버튼은 48px의 2×2 배치로 모으고 탄약 표시와 간격 확보. 수류탄은 기본 배치에서 능력 쌍 위로 이동하여 조이스틱·왼쪽 사격 버튼과의 겹침 방지. 저장된 사용자 위치는 인라인 설정을 계속 적용함.
- Chromium 뷰포트 852×393, 667×375, 568×320에서 홈 메뉴의 화면 내 배치와 기본 능력 버튼의 경계·수류탄 겹침 검사 통과. 390×844 및 1440×900도 확인. 실제 버튼 클릭으로 연습 메뉴→요원 선택을 검증하고, 창 크기 변경 후 저장한 위치(가로 20%, 세로 25%, 크기 1.2)가 유지됨을 확인. 모바일 실기기 검증은 별도.

## 확인하지 못한 범위와 후속 작업

- 로컬 신호 서버에 두 브라우저가 연결하고 PeerJS OFFER/ANSWER를 주고받는 데까지 확인했습니다. Chromium 관리 정책 `WebRtcIPHandling: disable_non_proxied_udp` 때문에 ICE 후보가 나오지 않아 실제 데이터 채널 연결 검사는 실패했습니다. 정책을 변경하지 않았습니다. `test:online`은 WebRTC를 허용하거나 정상 TURN을 제공하는 환경에서 이어서 실행해야 합니다.
- 운영 Upstash/Vercel, 실제 다른 기기·네트워크의 WebRTC/TURN, 모바일 실기기의 멀티터치·청감, 여러 시간의 GPU/메모리 검증은 수행하지 않았습니다.
- 랭크는 기존 보고 정책을 유지합니다. AI·비공개 방·관리자 변경 경기를 제외할지 사용자 선택을 요청했고 아직 확정되지 않았습니다. 보고 내용은 P2P 호스트에 의존하므로 서버가 경기 전체를 검증하는 구조는 아닙니다.
- 모든 음색은 코드 합성 기반이며 여러 스킨이 같은 계열을 공유합니다.
- 기존 전역 함수 래퍼·타이머의 완전한 통합, 엔진 내부 데이터/기능의 추가 분리, 남은 동적 대화상자의 접근성은 후속 구조 정리 대상입니다.
