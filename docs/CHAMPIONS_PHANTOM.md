# 챔피언스 팬텀 연결

팬텀에 `champions_atk`(공격·붉은빛), `champions_def`(수비·상아빛) 초월 스킨을 추가했다. 총 스킨 창 위쪽 **챔피언스** 탭 안에 전용 구매 화면이 있다. 그 안에서 색상, 발사음, 킬 배너·소리, 마무리, 살펴보기, 재장전을 미리 볼 수 있다. 보유한 색상을 누르면 팬텀에 장착되며 기존 계정 저장과 방의 스킨 동기화를 사용한다. 미보유 색상은 미리보기만 가능하다. 초월 코인 700개로 구매하거나 기존 **뽑기** 탭에서 다른 스킨과 함께 0.00000000000000001% 확률로 획득한다. 별도 챔피언스 뽑기는 만들지 않는다. 관리자 지급 항목은 `scout|champions_atk`, `scout|champions_def`다.

피해량·탄창·연사·판정은 팬텀 그대로다. 실제 마무리는 기존 규칙에 따라 일반전에서 마지막 적을 총으로 처치했을 때 한 라운드에 한 번 재생된다. 수류탄·능력·환경 피해, 다른 모드에는 적용하지 않는다. 모바일의 낮은 품질 설정과 동작 줄이기 설정을 따른다. 무기 살펴보기는 기존 Y 키와 터치 버튼을 사용한다. 재장전·꺼내기·사격은 기존 게임 손 모션을 유지하고 원본이 있으면 탄창·장전 손잡이 뼈대를 추가로 움직인다.

## 초월 등급과 초월 코인

무기고의 별도 **스킨 등급표**와 내 스킨 필터는 일반 → 희귀 → 영웅 → 전설 → **초월(5단계)** 순서다. 팬텀 공격·수비만 초월이며 기존 전설은 그대로다. 공유 데이터 `js/skin-tiers.js`를 게임·API·관리자 화면이 사용한다.

경기 완료 보상 기준(기존 경기 확인표와 60초 이상 경과)을 충족하면 승리·패배·무승부 모두 초월 코인 **1개**를 받는다. 연습/사격장·중도 이탈은 완료 보상을 만들지 않는다. 신규 코인 잔액은 0이며 기존 경기 수로 소급 지급하지 않는다. 골드와 별도로 계정/게스트 기록에 저장하고, 경기 확인표 소비·잔액 증가·재시도 영수증을 한 번에 저장해 재전송으로 중복 지급하지 않는다. 홈페이지와 초월 상점에서 잔액을 본다.

**공격/수비 스킨은 각각 700코인**이다. 초월 상점에서 두 번 눌러 구매를 확정하며, 서버는 가격을 700으로 고정한다. 골드는 사용하지 않는다. 부족한 잔액, 중복 보유, 동시 구매는 잔액을 음수로 만들지 않는다. 일일/주간 골드 상점에는 나오지 않으며 기존 관리자 지급 기능은 유지한다.

골드 뽑기에서는 초월 등급을 정확히 **0.00000000000000001% (1 / 10¹⁹)**로 별도 추첨한다. 암호학적 64비트 난수를 BigInt 정수로 읽고 범위 밖 표본을 다시 뽑아 나머지 연산의 편향을 없앤다. 보통 등급의 가중치와 독립적이며, 전설까지 전부 모았을 때의 보정이 초월로 자동 승급하지 않는다. 보유한 초월 스킨은 중복 지급하지 않는다. 일반 뽑기 가능 품목이 모두 소진되면 기존처럼 더 뽑을 수 없다.

## 원본 모델 자동 표시와 JAR 교체

제공된 JAR의 무기 모델/텍스처, 숫자 키프레임 애니메이션, 킬 배너 프레임/엠블럼, 마무리 용·뱀 모델/텍스처와 FX를 포함한 시각 데이터 33개를 `assets/champions-phantom/2026-0.1.0/`에 바이트 그대로 포함한다. 처음 접속한 브라우저에서도 수동 가져오기 없이 원본 총을 표시한다. 기본 팬텀에 색만 입힌 대체 모델을 챔피언스 미리보기로 표시하지 않는다. 로딩 중/실패 시에는 안내와 재시도 버튼을 표시하고, 실패한 리소스를 다른 외형으로 바꾸지 않는다.

PNG를 재인코딩하거나 해상도를 낮추지 않는다. 무기의 512×512 텍스처와 878개 상자를 유지하고 뼈대별로 합쳐 렌더링한다. manifest의 크기·SHA-256을 확인한 뒤 텍스처가 실제로 디코딩된 상태에서 적용한다. `npm run package:phantom -- /path/to/ChampionsPhantom2026-0.1.0.jar`로 같은 데이터를 다시 만들 수 있다. 테스트에 `PHANTOM_JAR`를 지정하면 패키지의 모든 파일이 제공 JAR 항목과 바이트 단위로 같은지도 검사한다.

**다른 원본 JAR 불러오기**로 선택한 파일은 이 기기·브라우저·사이트 주소의 IndexedDB에만 저장되며 새로고침 후 복원된다. 계정 API와 다른 플레이어에게 전송하지 않는다. 방에는 기존과 동일한 스킨 식별자만 보내고 모든 브라우저는 기본 원본 리소스를 자동으로 읽는다. **제공된 원본으로 복원**은 로컬 교체본을 지우고 기본 원본으로 돌아간다. 기본 표시에는 JAR 압축 해제나 IndexedDB 지원이 필요하지 않으며, 수동 JAR 가져오기는 `DecompressionStream('deflate-raw')`가 필요하다. 손상된 교체 파일은 현재 정상 팩을 유지한다.

사용자가 원본 제작자 본인임을 확인하고 이 게임에 원본을 사용하도록 요청했다. 원본 제작자 **Seafle** 표기와 `SOURCE-NOTICE.txt`를 유지한다. 원본 JAR·Java 클래스·내부 라이브러리 JAR은 포함하지 않는다. Minecraft 전용 카메라·손 위치·셰이더·자바 코드는 실행하지 않는다. Minecraft 전용 셰이더·입자·희생자 석상 패스와 배너 배치까지 원본 모드 전체를 완전히 재현한 것은 아니다.

## 원본 용·뱀 마무리와 8초 전환

### 2026-10-19 원본 렌더러 대조와 형태 수정

기존의 파일 SHA/도형 개수 검사는 원본 파일 보존만 증명했다. 그리는 좌표까지
일치한다고 판단하기에는 부족했다. 제공 JAR에 포함된 GeckoLib 4.4.4의
`BakedModelFactory.Builtin`, `VertexSet`, `GeoQuad`, `RenderUtils`를 읽어 대조한 결과,
기존 공용 변환기에 마무리의 X 좌표 반전·X/Y 회전 부호·면별 UV 배치 차이가 있었다.
머리·턱·뿔·몸통과 눈 효과가 원본의 위치에서 어긋날 수 있던 렌더링 오류다.

`js/gecko-finisher-rig.js`가 마무리 모델만 별도로 변환한다. 원본 JSON/PNG는 수정하지
않으며, 무기/네온의 기존 변환 경로에도 적용하지 않는다. 부모의 절대 피벗을 순서대로
곱하는 별도 기준 계산과 실제 렌더링 정점을 비교한다. 검은 용 7,704개, 크림색 뱀
9,324개, 빨간 뱀 9,216개 정점에서 최대 오차는 원본 픽셀 단위 약 0.00000153이다.
제작자 `client.c.h`의 눈 좌표도 머리 표면과 맞는지 검사한다. 표면은 원본의 두 방향
확산광/20% 자체발광 수식으로 명암을 주지만 Minecraft 전체 화면 합성까지 같다는 뜻은
아니다. 이 검사는 네이티브 Minecraft 실행 화면과의 픽셀 비교를 대체하지 않는다.

용·뱀 관절이 고정이고 주변 효과가 움직인다는 원본 구조는 그대로다. 아래에 적힌
리본/문양/입자 동작은 이식했지만, 원본 전체 패스·희생자 석상·화면 필터까지 모두
이식한 것은 아니다. 마무리 **전체가 원본과 100% 같다**고 설명하지 않는다.

이전의 임의 나선·삼각형 머리·왕관·회전을 제거하고 원본 `dragon_low`와 `serpent_cream` / `serpent_red`를 함께 표시한다. 원본 `client.c.b` 렌더러와 `c.a` 열거형을 `javap`으로 읽어 조합과 시점을 확인했다. 공격형은 검은 용·크림색 뱀, 수비형은 검은 용에서 흰 용으로 바뀌며 빨간 뱀을 사용한다. 용은 69개 뼈대·214개 상자, 크림색 뱀은 71개 뼈대·259개 상자, 빨간 뱀은 59개 뼈대·256개 상자를 유지한다. 텍스처는 용 512×256, 뱀 512×512 원본이며 첫 표시 전에 디코딩한다.

원본처럼 처치 후 2.66초에 모델을 표시하고 2.8초에 수비형 용의 색을 바꾼다. 원본의 15초 유지 시간을 요청에 맞게 4.34초로 줄여, 7~8초에는 원본 방식의 1초 페이드 후 전환한다. 원본의 고정 포즈·피벗·1/16 단위 변환을 유지하고 크기만 필요할 때 확대해 **플레이어 키의 최소 5배**를 보장한다. 현재 원본 모델 조합은 높이 약 19.19 게임 단위로, 기준 플레이어 2.31 단위의 약 8.3배다. 낮은 품질에서도 원본 상자를 생략하지 않는다. 미리보기는 무기를 잠시 숨기고 카메라 거리와 원거리 표시 범위를 조정해 같은 용·뱀 전체를 보여주며 정지하면 복원한다.

**용 몸통·머리의 관절 애니메이션은 제공된 원본 JAR에도 없다.** 전체 176개 제작자 클래스, 원본 모델 정점 셰이더, 애니메이션 JSON을 읽어 확인했다. 모델 렌더러 `client.c.b.d`는 고정 포즈를 그리고, `client.c.b.b.d`는 뼈대/상자를 순회해 그릴 뿐 시간에 따라 관절을 움직이지 않는다. 유일한 애니메이션 JSON의 22개 트랙도 총·손 전용이다. 몸을 흔들거나 회전시키는 임의 동작은 원본 동작으로 표시하지 않는다.

`js/phantom-finisher-motion.js`는 원본 `client.c.b`의 움직이는 주변 효과를 브라우저에 옮긴다. `i/j`의 흰색·빨간색 리본 9개는 0.41~1.25초에 원본 시작 간격, 지수 반경 감소, 각속도, 폭으로 감긴다. `h/m`의 별·문양·고리는 원본 구간에 표시되며 문양은 초당 30도로 회전한다. `p/q`는 2.66초 등장 직후 32개 빛줄기와 20개 회전 파편을 표시한다. `s`의 빛은 3초부터 0.6초 주기로 0.1초 동안 점멸하고 이어서 세 줄의 번개가 표시되며, 입자 40개가 상승·회전하고 빛줄기 14개가 내려온다. `c.b.a`의 64비트 난수/오버플로와 `c.h` 좌표를 옮기고 처치 이벤트의 동일한 tick·위치를 사용해 호스트/게스트의 무작위 배치를 일치시킨다. 고정된 용·뱀과 움직이는 입자를 구분해서 검증한다.

FX PNG 10개는 원본 바이트와 해상도를 유지하고 모델과 함께 미리 디코딩한다. 브라우저의 빌보드/동적 버퍼와 알파·가산 혼합으로 렌더링한다. Minecraft의 전체 합성 셰이더·피해자 석상·화면 필터·모든 정적 궤적 패스까지 동일하게 복제한 것은 아니다. 동작 줄이기에서는 기존처럼 전체 마무리 시각 효과를 재생하지 않는다.

일반전에서 챔피언스 마지막 처치가 인정되면 **처치 시각부터 8초 후** 다음 라운드를 시작한다. 승리 점수에 도달한 경우에는 8초 후 경기 결과로 이동한다. 기존 전설 `champion`도 같은 8초를 사용하고 다른 스킨의 기존 라운드 대기 시간은 유지한다. 호스트가 남은 시간을 스냅샷에 보내며 다음 라운드·방 나가기·경기 종료 시 마무리와 예약된 라운드 전환을 정리한다.

JAR 안에는 음원 파일이 없지만 원본 Java 상수 테이블에 노트블록 음원·음높이·볼륨·재생 시각이 있다. `scripts/extract-phantom-audio.py`가 클래스를 실행하지 않고 `javap` 목록의 상수만 읽어 1~5킬 연주를 추출했다. Minecraft 1.20.1의 원래 노트블록 Ogg 7개를 재인코딩 없이 보존하고 공식 자원 SHA-1 및 SHA-256을 기록했다. 브라우저는 이 음원을 원본 타이밍과 음높이(원본처럼 0.5~2 제한), 볼륨으로 재생한다. 팬텀 처치에는 일반 처치·헤드샷·멀티킬 합성 멜로디가 겹치지 않는다. 미리보기 버튼을 다시 누르면 1~5킬 연주를 순환한다. 공유 음량·효과음 설정은 그대로 적용하며 발사·마무리 소리와 Minecraft 셰이더는 DFDF의 기존 연출이다.

정찰 소총과 팬텀은 표시 이름을 서로 바꾼다. 내부 ID는 carbine=정찰 소총, scout=팬텀이며 모델·성능은 유지한다. 기존 돌격소총(rifle)·카빈(carbine)에 있던 챔피언스 구매분은 첫 계정 조회/저장 때 팬텀(scout)으로 옮긴다. 코인·골드를 재청구하지 않고 중복 소유를 합치며, 팬텀에 다른 스킨을 장착해 뒀다면 그 선택을 유지한다. 장착 변경의 저장 시각을 갱신해 오래된 돌격소총 설정이 되살아나지 않게 한다.

브라우저에 더 최신인 돌격소총·카빈 챔피언스 장착 캐시가 있어도 먼저 팬텀으로 옮긴 뒤 계정과 동기화한다. 현재 팬텀의 다른 선택은 유지하고, 최근 뽑기 기록의 챔피언스 항목도 팬텀으로 표시한다. `npm run test:phantom-carbine`은 기존 계정/로컬 캐시 이관·무료 유지·상점 장착·팬텀의 원본 총 모델·돌격소총 기본 모델을 확인한다.

오디오를 다시 만들려면 JDK의 `javap`, Python과 설치된 Minecraft 1.20.1 자원이 있는 환경에서 `python scripts/package-phantom-audio.py <원본.jar> <.minecraft/assets>`를 실행한다. 연주 출처는 Seafle, 노트블록 녹음 출처는 Mojang Studios로 구분한다.

## 검증

```sh
npm run check
npm test
npm run dev
# 다른 터미널: Playwright 설치 및 필요하면 CHROME_BIN 지정
npm run test:phantom
npm run test:phantom-carbine
npm run test:phantom-loading
npm run test:phantom-audio
npm run test:champions-finish
# 로컬 PeerServer 모듈을 DFDF_PEER_SERVER_MODULE로 지정할 수 있음
npm run test:champions-finish-online
npm run test:phantom-motion
# 선택: 보유한 JAR의 절대경로를 PHANTOM_JAR 환경변수에 설정한 뒤 다시 실행
```

`DFDF_PLAYWRIGHT_MODULE`, `CHROME_BIN`, `DFDF_BASE_URL`, `SHOT_DIR`는 기존 브라우저 테스트와 같다. 새 브라우저에서 원본 자동 표시/878개 구성 유지/512×512 텍스처/로딩 실패와 재시도/별도 구매 탭/등급표/초월 필터/정확한 확률 표시/경기 보상 반영/700코인 구매/소유권/장착/배너/마무리 정리/반응형을 검사한다. `PHANTOM_JAR`가 있으면 실제 JAR 교체·계정 장착/로컬 자산 복원·기본 원본 복원도 검사한다. 스크린샷은 git에서 제외되는 `test-results/phantom`에 저장된다. 테스트 구매/관리자 지급은 메모리 API 도구를 사용하며 실제 계정이나 결제를 변경하지 않는다.

브랜치와 PR은 검토용이다. 사용자 승인 전 병합하거나 운영 배포하지 않는다.

`test:champions-finish`는 실제 상점 버튼과 일반전 마지막 처치를 사용해 원본 도형 수·공격/수비 조합·카메라 표시 범위·최소 5배 크기·7.999초 유지·8초 전환·방 나가기 취소를 검사한다. `test:champions-finish-online`은 실제 로컬 WebRTC 호스트/게스트 두 브라우저로 남은 시간·원본 뱀·다음 라운드·효과 정리를 검사한다. 스크린샷은 `test-results/champions-finish/`에 저장한다. 단위 테스트는 일반 라운드의 3.6초 유지, 마지막 라운드 결과 화면, 중복 점수/전환 방지도 검사한다. Android 기기와 실제 상점 결제는 이 검증에 포함되지 않는다.

`test:phantom-motion`은 실제 미리보기 버튼을 눌러 원본 리본의 렌더링 픽셀·문양의 정점 위치·입자의 위치가 시간에 따라 변하는지, 용 관절은 원본처럼 고정인지, 텍스처 디코딩·WebGL 오류·8초 정리·동작 줄이기를 검사한다. 스크린샷은 `test-results/phantom-motion/`에 저장한다. 순수 수학 테스트는 원본 난수의 음수/오버플로, 리본 반경, 시간 경계, 점멸 주기, 멀티플레이용 결정성을 검사한다.

총별 장착과 내 스킨 탭에 들어갈 때 보유 정보를 다시 확인합니다. 잠긴 스킨을 눌렀을 때도 서버 보유 여부를 갱신하여, 다른 창·기기의 구매나 지급으로 보유하게 된 스킨을 같은 클릭으로 장착할 수 있습니다. 이미 진행 중인 조회가 있으면 새 조회를 이어서 실행하며, 다른 총·탭·계정으로 바뀐 뒤 도착한 이전 클릭 결과는 장착하지 않습니다. 미보유 스킨은 계속 미리보기만 가능합니다.

## 원본 미리듣기와 바닥 능력 수정 (2026-10-19)

살펴보기의 `inspect` 104음, 마무리의 `finisher_music` 305음을 원본 클래스의 상수표에서 추가 추출한다. 루프 경계 0.6~10.2초와 0~19.2초를 데이터에 보존한다. 미리보기에서는 살펴보기 10.2초 구간을 재생하고, 마무리 음악은 원본의 3.03초 시점에 시작해 요청한 8초 마무리 종료에 함께 멈춘다. 게임 내 살펴보기 음악은 실제 살펴보기 동작이 끝나거나 중단되면 멈춘다. 이 변경이 원본의 모든 발사·장전·마무리 효과음을 이식했다는 뜻은 아니다.

기존 7개 노트블록 녹음은 그대로 두고 hat/snare 2개를 Minecraft 1.20.1 로컬 자원에서 원본 바이트로 추가한다. `music-sequences.json`에도 원본 JAR/클래스 SHA-256을 기록한다. 합성 멜로디로 음악을 대신하지 않는다.

미리듣기는 클릭 중 먼저 오디오를 활성화하고 음원 로딩을 기다린다. 실전 처치음의 1.5초 지연 폐기 규칙은 명시적인 미리듣기에 적용하지 않는다. 로딩·음소거·실패와 재시도를 화면에 알리고, 중지/다른 미리보기/탭 닫기 이후에는 늦게 도착한 요청이 다시 소리를 내지 않는다. 이전 살펴보기 프레임이 새 미리보기를 중지시키는 경쟁도 막는다.

`npm run test:phantom-audio`는 강제 `AudioContext.resume()` 없이 실제 버튼으로 첫 로딩 지연, 원본 살펴보기/마무리 음악의 오디오 신호, 다섯 처치 연주, 중지/취소, 효과음 설정, 503 오류 후 재시도를 검사한다. 오디오 분석기의 신호를 확인하는 Chromium 검사이며 실제 휴대폰 스피커에서 들었다는 뜻은 아니다.

기존 설치형 웹 앱은 `/assets`를 URL별로 보관하므로, 7개 음원만 적힌 이전 목록을 재사용하지 않도록 음원 목록 요청에 버전을 붙인다. 원본 음원·맵·텍스처 캐시 전체를 지우지 않는다. 브라우저 검사는 구버전 주소의 7개 목록을 흉내 낸 응답을 두고 새 주소가 이를 피하는지도 검사한다.
