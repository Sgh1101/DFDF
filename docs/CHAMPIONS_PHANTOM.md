# 챔피언스 팬텀 연결

돌격소총에 `champions_atk`(공격·붉은빛), `champions_def`(수비·상아빛) 초월 스킨을 추가했다. 총 스킨 창 위쪽 **챔피언스** 탭 안에 전용 구매 화면이 있다. 그 안에서 색상, 발사음, 킬 배너·소리, 마무리, 살펴보기, 재장전을 미리 볼 수 있다. 보유한 색상을 누르면 돌격소총에 장착되며 기존 계정 저장과 방의 스킨 동기화를 사용한다. 미보유 색상은 미리보기만 가능하다. 초월 코인 700개로 구매하거나 기존 **뽑기** 탭에서 다른 스킨과 함께 0.00000000000000001% 확률로 획득한다. 별도 챔피언스 뽑기는 만들지 않는다. 관리자 지급 항목은 `rifle|champions_atk`, `rifle|champions_def`다.

피해량·탄창·연사·판정은 돌격소총 그대로다. 실제 마무리는 기존 규칙에 따라 일반전에서 마지막 적을 총으로 처치했을 때 한 라운드에 한 번 재생된다. 수류탄·능력·환경 피해, 다른 모드에는 적용하지 않는다. 모바일의 낮은 품질 설정과 동작 줄이기 설정을 따른다. 무기 살펴보기는 기존 Y 키와 터치 버튼을 사용한다. 재장전·꺼내기·사격은 기존 게임 손 모션을 유지하고 원본이 있으면 탄창·장전 손잡이 뼈대를 추가로 움직인다.

## 초월 등급과 초월 코인

무기고의 별도 **스킨 등급표**와 내 스킨 필터는 일반 → 희귀 → 영웅 → 전설 → **초월(5단계)** 순서다. 팬텀 공격·수비만 초월이며 기존 전설은 그대로다. 공유 데이터 `js/skin-tiers.js`를 게임·API·관리자 화면이 사용한다.

경기 완료 보상 기준(기존 경기 확인표와 60초 이상 경과)을 충족하면 승리·패배·무승부 모두 초월 코인 **1개**를 받는다. 연습/사격장·중도 이탈은 완료 보상을 만들지 않는다. 신규 코인 잔액은 0이며 기존 경기 수로 소급 지급하지 않는다. 골드와 별도로 계정/게스트 기록에 저장하고, 경기 확인표 소비·잔액 증가·재시도 영수증을 한 번에 저장해 재전송으로 중복 지급하지 않는다. 홈페이지와 초월 상점에서 잔액을 본다.

**공격/수비 스킨은 각각 700코인**이다. 초월 상점에서 두 번 눌러 구매를 확정하며, 서버는 가격을 700으로 고정한다. 골드는 사용하지 않는다. 부족한 잔액, 중복 보유, 동시 구매는 잔액을 음수로 만들지 않는다. 일일/주간 골드 상점에는 나오지 않으며 기존 관리자 지급 기능은 유지한다.

골드 뽑기에서는 초월 등급을 정확히 **0.00000000000000001% (1 / 10¹⁹)**로 별도 추첨한다. 암호학적 64비트 난수를 BigInt 정수로 읽고 범위 밖 표본을 다시 뽑아 나머지 연산의 편향을 없앤다. 보통 등급의 가중치와 독립적이며, 전설까지 전부 모았을 때의 보정이 초월로 자동 승급하지 않는다. 보유한 초월 스킨은 중복 지급하지 않는다. 일반 뽑기 가능 품목이 모두 소진되면 기존처럼 더 뽑을 수 없다.

## 원본 모델 자동 표시와 JAR 교체

제공된 JAR의 무기 모델/텍스처, 숫자 키프레임 애니메이션, 킬 배너 프레임/엠블럼, 마무리 용 모델/텍스처 19개를 `assets/champions-phantom/2026-0.1.0/`에 바이트 그대로 포함한다. 처음 접속한 브라우저에서도 수동 가져오기 없이 원본 총을 표시한다. 기본 돌격소총에 색만 입힌 대체 모델을 챔피언스 미리보기로 표시하지 않는다. 로딩 중/실패 시에는 안내와 재시도 버튼을 표시하고, 실패한 리소스를 다른 외형으로 바꾸지 않는다.

PNG를 재인코딩하거나 해상도를 낮추지 않는다. 무기의 512×512 텍스처와 878개 상자를 유지하고 뼈대별로 합쳐 렌더링한다. manifest의 크기·SHA-256을 확인한 뒤 텍스처가 실제로 디코딩된 상태에서 적용한다. `npm run package:phantom -- /path/to/ChampionsPhantom2026-0.1.0.jar`로 같은 데이터를 다시 만들 수 있다. 테스트에 `PHANTOM_JAR`를 지정하면 패키지의 모든 파일이 제공 JAR 항목과 바이트 단위로 같은지도 검사한다.

**다른 원본 JAR 불러오기**로 선택한 파일은 이 기기·브라우저·사이트 주소의 IndexedDB에만 저장되며 새로고침 후 복원된다. 계정 API와 다른 플레이어에게 전송하지 않는다. 방에는 기존과 동일한 스킨 식별자만 보내고 모든 브라우저는 기본 원본 리소스를 자동으로 읽는다. **제공된 원본으로 복원**은 로컬 교체본을 지우고 기본 원본으로 돌아간다. 기본 표시에는 JAR 압축 해제나 IndexedDB 지원이 필요하지 않으며, 수동 JAR 가져오기는 `DecompressionStream('deflate-raw')`가 필요하다. 손상된 교체 파일은 현재 정상 팩을 유지한다.

사용자가 원본 제작자 본인임을 확인하고 이 게임에 원본을 사용하도록 요청했다. 원본 제작자 **Seafle** 표기와 `SOURCE-NOTICE.txt`를 유지한다. 원본 JAR·Java 클래스·내부 라이브러리 JAR은 포함하지 않는다. Minecraft 전용 카메라·손 위치·셰이더·자바 코드는 실행하지 않는다. 용 이동/나선/왕관과 배너 배치는 DFDF에 맞춘 연출이므로 원본 모드 전체의 완전한 재현은 아니다.

JAR 안에는 음원 파일이 없지만 원본 Java 상수 테이블에 노트블록 음원·음높이·볼륨·재생 시각이 있다. `scripts/extract-phantom-audio.py`가 클래스를 실행하지 않고 `javap` 목록의 상수만 읽어 1~5킬 연주를 추출했다. Minecraft 1.20.1의 원래 노트블록 Ogg 7개를 재인코딩 없이 보존하고 공식 자원 SHA-1 및 SHA-256을 기록했다. 브라우저는 이 음원을 원본 타이밍과 음높이(원본처럼 0.5~2 제한), 볼륨으로 재생한다. 팬텀 처치에는 일반 처치·헤드샷·멀티킬 합성 멜로디가 겹치지 않는다. 미리보기 버튼을 다시 누르면 1~5킬 연주를 순환한다. 공유 음량·효과음 설정은 그대로 적용하며 발사·마무리 소리와 Minecraft 셰이더는 DFDF의 기존 연출이다.

기존 카빈 구매분은 첫 계정 조회/저장 때 돌격소총으로 옮긴다. 코인·골드를 재청구하지 않고 중복 소유를 합치며, 돌격소총에 다른 스킨을 장착해 뒀다면 그 선택을 유지한다. 장착 변경의 저장 시각을 갱신해 오래된 카빈 설정이 되살아나지 않게 한다.

오디오를 다시 만들려면 JDK의 `javap`, Python과 설치된 Minecraft 1.20.1 자원이 있는 환경에서 `python scripts/package-phantom-audio.py <원본.jar> <.minecraft/assets>`를 실행한다. 연주 출처는 Seafle, 노트블록 녹음 출처는 Mojang Studios로 구분한다.

## 검증

```sh
npm run check
npm test
npm run dev
# 다른 터미널: Playwright 설치 및 필요하면 CHROME_BIN 지정
npm run test:phantom
npm run test:phantom-loading
npm run test:phantom-audio
# 선택: 보유한 JAR의 절대경로를 PHANTOM_JAR 환경변수에 설정한 뒤 다시 실행
```

`DFDF_PLAYWRIGHT_MODULE`, `CHROME_BIN`, `DFDF_BASE_URL`, `SHOT_DIR`는 기존 브라우저 테스트와 같다. 새 브라우저에서 원본 자동 표시/878개 구성 유지/512×512 텍스처/로딩 실패와 재시도/별도 구매 탭/등급표/초월 필터/정확한 확률 표시/경기 보상 반영/700코인 구매/소유권/장착/배너/마무리 정리/반응형을 검사한다. `PHANTOM_JAR`가 있으면 실제 JAR 교체·계정 장착/로컬 자산 복원·기본 원본 복원도 검사한다. 스크린샷은 git에서 제외되는 `test-results/phantom`에 저장된다. 테스트 구매/관리자 지급은 메모리 API 도구를 사용하며 실제 계정이나 결제를 변경하지 않는다.

브랜치와 PR은 검토용이다. 사용자 승인 전 병합하거나 운영 배포하지 않는다.
