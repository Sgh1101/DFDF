## 검사 범위

- `npm run check`: 외부 JS 97개 및 HTML 문법.
- 실제 임시 Redis 7.4.2 Lua를 포함한 `npm test`: **54개 통과, 실패/건너뜀 0개**.
- `test:browser`: 홈→요원 선택→무기고/소리/피니셔→사격→결과→로그아웃.
- `test:regression`: 즐겨찾기·모드 안내·포커스, RPG 발사 뒤 무기 교체, 부활·수류탄, 12회 경기 반복.
- `test:followup`: 방 목록·갱신 실패, 전용 자원 해제, CDP 멀티터치/취소, 버튼 배치 저장/취소, 계정 분리·다른 탭 로그아웃.
- `test:maps`: 장치·사이트 자원 해제, 문 조작, 6회 맵 재로딩. geometry 수 30 유지.
- `test:startup`: 엔진/스킨 응답 지연, 초기 버튼과 바로가기, 뽑기, 보이는 초상화.
- `test:home-layout`: 5개 화면 크기의 원래 스타일·배치·메뉴 클릭.
- `test:network-recovery`: 두 브라우저의 대기실 자리/팀/요원 복구, 상태 채널 상실 시 입력/스냅샷 대체, 경기 중 같은 요원 복구, 신호 재접속, 복구 중 나가기→재참가, 세 번째 브라우저의 진행 중 경기 참가.
- 실제 HTTP/API/임시 Redis 통합 흐름: 로그인→스킨 저장→뽑기 결과→UI 반영, 이동·문 조작·스파이크 설치/해제 통과. 브라우저 오류 0개.

진행 중 참가를 포구 맵에서도 확인해 새 브라우저에 같은 맵과 조작 가능한 요원 1명이 생성되는 것을 확인했습니다.

`network-recovery`는 실제 게임 스크립트를 실행하되 PeerJS 전송만 통제된 테스트 연결로 대체합니다. WebRTC 연결 성공이나 실제 이동통신 품질을 증명하는 검사는 아닙니다.

## 실제 네트워크 검증 한계

`test:online`에서 로컬 PeerJS 신호 서버와 두 브라우저의 OFFER/ANSWER 교환까지 확인했습니다. 데이터 채널은 열리지 않아 **실제 WebRTC 검사는 실패**했습니다. 현재 관리 정책은 `WebRtcIPHandling: disable_non_proxied_udp`이고, 이 검사의 ICE 서버는 빈 목록입니다. 정책을 변경하거나 우회하지 않았습니다.

운영 TURN 설정은 연결된 Vercel 팀에서 해당 프로젝트가 조회되지 않아 확인하지 못했습니다. 이를 운영 TURN이 없다는 증거로 간주하지 않습니다. 운영 TURN/다른 기기·네트워크에서 실제 끊김과 복구를 확인해야 합니다. 모바일 실기기, 앱/OS의 백그라운드 중단, 장시간 성능도 별도입니다.

이번 검증은 운영 계정·Redis 데이터를 변경하지 않았습니다. 실제 HTTP/API/Redis 검사는 별도 임시 저장소를 사용합니다.
