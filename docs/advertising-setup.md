# 광고 활성화 전 확인

현재는 **광고·선택적 분석을 로드하지 않는다.** ads-config.json은 도입 준비 기록이고, advertising-policy.js는 순수한 허용 판단 함수다. 광고 SDK 로더는 이 변경에 없다. 설정을 true로 바꿔도 광고가 나오지 않는다. privacy-preferences.js의 브라우저 선호는 인증 CMP나 제3자 동의 증명이 아니다.

## 사이트 확인 코드

2026-11-04 사용자가 제공한 게시자 ID는 `ca-pub-3446698746925219`다. 홈페이지 `index.html`의 `<head>`에 `google-adsense-account` 메타 태그를 추가하고, 루트 `ads.txt`에 해당 Google 직접 판매자 레코드를 준비했다. 광고 SDK를 실행하지 않는 [Google의 메타 태그 확인 방법](https://support.google.com/adsense/answer/7584263?hl=ko)을 사용한다.

운영 배포 후 `https://13fps.xyz/`의 원본 HTML에 메타 태그가 있고 `https://13fps.xyz/ads.txt`가 HTTP 200으로 해당 레코드를 반환하는지 확인한다. 애드센스에서 **메타 태그** 확인 방법을 선택한 뒤 검토를 요청한다. 사이트 소유권 확인과 광고 게재 승인은 별개이며 실제 계정의 검토 결과는 아직 확인하지 않았다.

## 운영자가 실제 계정에서 처리할 단계

1. [AdSense 신청 자격](https://support.google.com/adsense/answer/9724?hl=ko)에 맞는 신청인으로 로그인한다. 신원·지급 정보·약관 수락은 계정 소유자가 직접 처리한다.
2. `13fps.xyz`를 [사이트 목록](https://support.google.com/adsense/answer/12169212?hl=ko)에 추가하고, 계정이 제공한 사이트 확인 방법을 사용한다. 게시자 ID는 실제 `ca-pub-` 값만 쓴다. 테스트·가짜 ID를 공개하지 않는다.
3. 자산 권리 기록의 미확인 항목을 해소한다. 단순히 맵을 다른 이름으로 부르거나 출처를 적는 것으로 허가를 대신하지 않는다.
4. 이용자 연령층·대상 지역을 검토한다. 아동용 설정과 개인화 제한을 적용하고 [인증 CMP 요건](https://support.google.com/adsense/answer/13554116?hl=ko)을 실제 계정에서 설정한다. 지역을 모르면 추정해서 동의 처리 완료로 간주하지 않는다.
5. 루트 ads.txt의 게시자 ID와 판매자 레코드가 실제 계정의 안내와 일치하는지 확인한다. 현재 레코드는 위 사용자가 제공한 게시자 ID를 사용한다.
6. 사이트 승인·CMP 설정·거절/철회 흐름을 확인한 후 별도 코드 리뷰로 SDK 로더와 광고 슬롯을 추가한다. `ADVERTISING_POLICY.evaluate`의 외부 consent는 실제 CMP가 확인한 값이어야 한다. 로컬 선호 값을 `cmpVerified`로 바꾸면 안 된다.

## 첫 도입의 범위

일반 배너 후보는 guide, controls, modes, maps, agents, patch-notes뿐이다. 홈의 로그인 카드, play.html의 모든 경기/상점/뽑기/채팅, 관리자, 문의·정책·오류·로딩 화면은 제외한다. 자동 광고를 쓸 경우에도 해당 URL 제외를 먼저 설정한다. 게임과 조작 버튼 주변 150px 이격은 [Google의 강력 권장](https://support.google.com/adsense/answer/2768340?hl=ko)이지 오클릭 안전을 보증하는 규칙이 아니다.

전면·보상형은 [H5 별도 신청](https://developers.google.com/ad-placement/docs/signup) 후에만 검토한다. 경기 중·리스폰·챔피언스 마무리에는 넣지 않는다. 매치 사이에서 광고 없음/닫기/취소 시 입력·음소거·포인터락·연결 상태가 복구되어야 한다. 서버 시간은 개별 이용자의 광고 때문에 중지하지 않는다.

일반 광고 클릭에 코인·뽑기권을 지급하지 않는다. 실제 광고 반복 노출/클릭 자동화를 금지하고 개발·브라우저 검증은 테스트 모드만 사용한다. 광고 수익이나 승인을 보장하지 않는다.

## 활성화 검증 기록

- [ ] 실제 신청인·게시자 ID 및 사이트 승인 확인
- [ ] 실제 이용자 연령층·지역과 아동용 광고 처리 결정
- [ ] 인증 CMP에서 동의·거절·철회·정보 부족 경로 검증
- [ ] 루트 ads.txt 필요 여부 및 판매자 정보 확인
- [ ] 테스트 광고로 데스크톱·실제 Android/iPhone의 화면 회전·조작·복귀 검증
- [ ] 광고 없음/차단/오프라인에도 게임 시작·진행 가능
- [ ] 실제 게재·정산과 테스트 모드 결과를 구분해 보고

## 2026-11-04 심사 중인 현재 점검 방법

- `npm run check:ads`: 현재 자산의 지문과 광고 SDK 추가 여부를 검사한다. 광고가 꺼져 있고 증빙이 아직 없는 상태는 숨기지 않고 `ready:false`와 사유를 출력한다. 이것은 광고 활성화 승인 검사가 통과했다는 뜻이 아니다.
- `node scripts/check-ad-readiness.js --require-ready`: 활성화 준비 여부를 요구한다. 현재는 심사·성인 신청자·대상 연령/미성년 처리·지역/CMP·권리 항목이 남아 있어 종료 코드1이 정상이다.
- 사이트 상태는 사용자 답변에 따라 `in-review`로 기록했다. 신청자 신원이나 나이를 채팅으로 보내지 않는다. 성인 신청자/보호자 경로는 실제 계정에서 확인하고 완료 사실만 기록한다.
- `monetization-review.json`의 `assets`에는 황혼 지구4개, SGH나비칼12개의 현재 배포 파일 지문을 보존했다. 제공 사실·직접 만들었다는 일반 진술·이름/색상 변경만으로 타인의 구조·모션·음원 권한까지 확인했다고 쓰지 않는다. 파일이 바뀌거나 항목이 빠지면 검토를 다시 요구한다. 전체 자산 재검토도 별도 항목이다.
- 권리 확인에는 제작자/원권리자, 대상 파일·버전, 웹 게임 이용·수정·재배포·광고 수익화 범위가 필요하다. 비공개 증빙은 안전하게 보관하고 공개 JSON에는 개인정보나 계약서 대신 내부 기록 참조만 남긴다. 허가가 없다면 독자 교체/제외를 먼저 결정한다. 광고 OFF는 공개 자료 사용권을 해결하지 않는다.
- 인증 CMP는 실제 공급자 설정과 거절/철회/오류 경로 검증이 필요하다. 기존 로컬 개인정보 선호를 `cmpVerified:true`로 옮기지 않는다. EEA/영국/스위스의 개인 맞춤 광고에는 Google 인증TCF CMP 요건이 적용된다. 이는 비개인화/제한 광고의 별도 처리 가능성과 구분한다. ([공식 CMP 요건](https://support.google.com/adsense/answer/13554116), [비개인화 광고](https://support.google.com/adsense/answer/9007336))
- `evaluate(config, pathname, consent, review)`는 검토 기록과 `status:'ready'`, 유효한 `expiresAt`, 광고 동의·CMP 확인·비미성년 처리를 요구한다. 이것은 향후 실제 CMP 연결 계약이며 현재 SDK를 불러오지 않는다. `expiresAt`는 어댑터가 실제 동의 정책에 따라 정해야 하며 이 저장소가 법적 동의 유효 기간을 임의로 정하지 않는다.
- JSON을 수동으로 true로 고치는 것으로 계정 승인·사용권·CMP 인증이 생기지 않는다. 광고 게재 전 별도 SDK/슬롯 구현과 실제 지역별 동의 검증이 남는다. 지금 심사 준비 개선만으로 Google 승인을 보장하지 않는다.

## 사이트 이용자에게 보이는 개선

로그인 전 홈은 게임 방식·자체 포구 맵 이미지·조작/팀 역할/초대 코드 안내와 가이드 링크를 먼저 보여 준다. 자바스크립트 없이 소개와 가이드를 읽을 수 있다. 무료 시작 링크는 기존 게스트 버튼으로 안내하고, 로그인/가입·계정 대시보드·초대 URL 동작은 유지한다. 소개 페이지의 게스트/랭크·기기 성능 설명과 제작·출처 안내를 현행 기능에 맞춘다. 기존 개인정보 방침은 이미 광고 미실행과 로컬 선호/CMP 차이를 안내하므로 실제 처리 변경 없이 시행일만 바꾸지 않는다.
