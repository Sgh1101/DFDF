# 네온 요원 연결

**혼자 하기 또는 방의 요원 선택 → 네온 → 전투 투입**으로 사용한다. 기존 요원 뒤에 추가해 기존 요원 식별자와 순서를 유지한다. 요원 43명, 능력 172개다.

| 키 | 능력 | DFDF 동작 |
| --- | --- | --- |
| Q | 릴레이볼트 | 0.35초 준비 후 날아가 한 번 튕긴다. 첫 충돌·마지막 착탄 지점에서 0.7초 뒤 반경 3.5m, 3초 뇌진탕. 벽에 가려진 적 제외. 2회, 200크레딧 |
| E | 고속기어 | 10초간 이동 속도 1.4배. 우클릭/모바일 조준으로 6m·0.8333초 슬라이딩. 2킬마다 슬라이딩 충전. 일반 총 사격으로 질주 해제. 재사용 30초 |
| C | 추월차선 | 길이 최대 30m, 간격 3.6m의 전기 장벽 두 개. 양옆 시야를 6초 차단하고 중앙 통로는 유지. 1회, 300크레딧 |
| X | 오버드라이브 | 7포인트. 20초간 손에서 40m 빔을 발사해 0.1초당 피해 18. 고속기어·슬라이딩 재충전 |

피해와 상태 이상은 방장이 결정한다. 능력 요청·시전 재생은 기존 경로를 사용하고 질주·슬라이딩·궁극기·뇌진탕 상태를 스냅샷으로 보완한다. 손님은 직접 피해를 주지 않는다. 사망·라운드 초기화·요원 변경 때 전용 상태를 지운다. 능력 없는 모드에서는 기존 제한을 따른다.

## 원본과 적용 범위

`SeafleNeonValorant-NoSound-1.0.0-release.jar`는 **Seafle - UnfixedGames**의 Fabric 1.20.1 모드다. JAR에는 **전신 캐릭터 모델이 없다**. 두 팔 모델/일반·충전 텍스처, 스킬 아이콘 4개, HUD 장식, 전기 파티클 12장, 팔 동작과 슬라이딩 데이터가 있다.

이 PNG·JSON **28개를 바이트 그대로** `assets/neon/1.0.0/`에 복사했다. 해상도를 줄이거나 PNG를 재인코딩하지 않았고 팔의 상자 3개·원본 UV를 유지했다. 브라우저는 크기·SHA-256을 검증하고 텍스처 디코딩이 끝난 뒤 사용한다. `manifest.json`에 원본 JAR 해시와 각 항목의 해시가 있다.

전신 복장과 초상화는 DFDF의 기존 캐릭터 제작 방식으로 새로 만들었다. 원본 팔은 스킬 사용·질주·궁극기에서, 원본 스킬 아이콘은 선택 화면과 HUD에서, 원본 파티클은 질주·궁극기에서 사용한다. 슬라이딩 때 원본 몸 높이·다리 회전을 DFDF 뼈대로 옮기고 카메라·웅크린 판정을 연결한다. 숫자 키프레임의 선형/Catmull-Rom 보간을 지원하며 표현식·Molang은 실행하지 않는다.

속도 1.4배와 슬라이딩 6m·0.8333초는 원본 Java 상수에서 확인했다. 지속시간·비용·피해량·카메라 위치·이펙트는 DFDF에 맞춘 조정이다. Minecraft 자바 코드·플러그인·런타임을 실행하는 방식이 아니며, 원본 모드 전체와 동일한 렌더링이라고 주장하지 않는다. 제공된 **NoSound** 버전에는 캐릭터 음성/음원이 없다.

재패키징:

```sh
python scripts/package-neon-assets.py /path/to/SeafleNeonValorant-NoSound-1.0.0-release.jar
```

## 검증

```sh
npm run check
npm test
npm run dev
# Playwright/Chrome 경로를 환경에 맞게 지정한 다른 터미널에서:
npm run test:neon
# 로컬 PeerServer의 peer 모듈을 설치하거나 DFDF_PEER_SERVER_MODULE로 지정:
npm run test:neon-online
```

단위 검사는 원본 파일의 해시·크기와 숫자 보간을 확인한다. 브라우저 검사는 실제 선택 화면, 팔 지오메트리, 속도, 슬라이딩 거리/재충전, 양옆 시야 차단/중앙 통로, 충격탄의 뇌진탕, 빔 피해와 손님 피해 차단을 확인한다. 별도 검사에서는 브라우저 두 개를 로컬 WebRTC로 연결해 손님의 능력 요청과 방장 처리, 상태 동기화, 뇌진탕 만료를 검증한다.

계정·구매 API는 테스트용 메모리 저장소를 사용한다. 실제 Redis 검사는 별도 환경이 필요하다. Android 기기·실제 스토어 결제 검증과는 구분한다.
