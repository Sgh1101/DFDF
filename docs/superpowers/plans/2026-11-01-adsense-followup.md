# 광고 준비 후속 작업

사용자 요청: 남은 작업 중 에이전트가 할 수 있는 것을 진행한다. 기존 `codex/adsense-readiness`의 완료된 변경 위에서 작업한다.

## 선택한 범위

계정 정보가 필요한 광고 활성화를 먼저 시도하는 대신, 실제로 실행할 수 있는 보안 통합과 브라우저 캐시 검증을 먼저 완료한다. 전체 보안 PR을 main에 병합하는 방식은 별도 승인 규칙과 충돌하므로 사용하지 않는다. PR #111의 검토된 변경을 이 검토용 브랜치에 통합하고 보고 모드 CSP를 유지한다. Google 계정은 읽기만 확인하며 약관·신원·지급 정보를 대신 확정하지 않는다.

클로드의 보안 head는 `6116eba68bb96cab5d5c872d9949a362ef15fc36`, 기준 main은 `32a422e75d78c202f8203fbd5ce0051d50ab8647`이다. 챔피언스와 단색 블록 텍스처는 기준 main과 바이트 동일하게 유지한다. 다른 사람이 작업 중인 연습장·챔피언스 시안 worktree는 수정하지 않는다.

## 작업 순서

- [x] PR #111을 코드 규칙과 원래 요구사항 두 관점으로 검토하고 결과를 기록한다.
- [x] 검토된 보안 변경을 이 브랜치에 통합한다. 새 가입 8자, 기존 짧은 비밀번호 로그인 유지, CSP는 보고 모드. 변경된 HTML에 맞춰 헤더 해시를 재생성한다.
- [x] 실제 로컬 화면/경로를 탐색한 뒤 서비스 워커를 허용한 브라우저에서 과거 캐시→업데이트→새 자산·오프라인→복귀를 검사한다. 외부 네트워크·운영 데이터는 쓰지 않는다.
- [x] 가능한 로컬 장치/Redis 검사 환경과 AdSense 계정 상태를 실제로 확인한다. 미확인 항목을 완료로 표시하지 않는다.
- [x] 단위·보안 헤더·사이트·시작·캐시 관련 브라우저 검증을 실행하고, 현재 커밋/소스 지문과 결과·남은 계정 작업을 기록한다.
- [ ] 후속 사용자 요청에 따라 정확한 커밋을 기존 Vercel 프로젝트에 배포하고 운영 응답을 확인한다. main 병합은 별도로 수행하지 않는다.

## 경계와 한계

실제 광고 SDK/광고 슬롯은 사이트 승인·권리·대상 이용자·인증 CMP가 확인되기 전에는 넣지 않는다. 인증 정보를 읽거나 저장소에 넣지 않고, 계정/운영 Redis 데이터는 수정하지 않는다. main 병합은 수행하지 않는다. 배포는 후속 명시적 요청으로 승인되었고 기존 프로젝트에서 진행한다. 이미 설치된 도구를 우선 사용하며 없는 실기기나 비실행 Docker를 검사 통과로 계산하지 않는다. 새 시스템 소프트웨어 설치를 요구하지 않는다.
